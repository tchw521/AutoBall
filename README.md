# AutoBall

Android 本地自动化点击器。以悬浮球为交互主体，支持 **点击 / 录制 / JS 脚本** 三种执行方式，
执行层同时提供 **无障碍服务** 与 **Shizuku** 两条并行通道——**任意一种授权可用，即可运行完整脚本**。

> 定位：本地运行、明确授权、随时可停的辅助自动化工具。
> 不联网上传任何数据，不用于任何第三方平台的刷量、代打或外挂场景。

## 三种执行方式

| 方式 | 说明 | 落地格式 |
|---|---|---|
| 点击 | 手工逐步添加 20 类动作，动态表单配置参数 | 动作流（结构化 JSON） |
| 录制 | 采集层接管内触摸 → 抬手立即补发 → 回声抑制 → 编译为动作 | 动作流（可逐条删改） |
| JS 脚本 | 手写脚本，调用宿主 API 编排复杂逻辑 | JS 源码 |

三种来源在运行时归一为同一个执行链路，共用同一套后端路由。

## 双授权并行

两种后端对等存在，按 **动作所需能力** 路由，而不是让用户去猜该用哪个接口：

| 能力 | 无障碍 | Shizuku |
|---|---|---|
| 坐标点击 / 长按 / 滑动 | ✅ | ✅ |
| 真正多指 | 实验性（依赖并行 stroke，ROM 差异大） | 降级为顺序单指 |
| 文本输入 | 需输入框获得焦点 | `input text`，能力完整 |
| 截图取色 | API 30+，部分场景受限 | `screencap`，速度快 |
| 控件节点查找 | ✅ 独有 | ❌ |
| 按键 / 启动应用 / 打开链接 | 部分 | ✅ |

运行前会做一次 **能力体检**，明确告知：哪些动作可完整执行、哪些会降级、哪些无法执行。
单个动作失败时自动回退到另一个后端，并把降级原因写进运行日志。

## 工程约束

- **零第三方运行时依赖**：不使用 androidx / 协程 / 序列化库，JSON 用平台自带 `org.json`
- 包体目标 ≤6MB：QuickJS 单 ABI 约 350KB，图像匹配与 OCR 按需下载、绝不进初始包
- 目标 Android 12+，最低 Android 7.0（低版本自动降级）
- `minSdk 24 / targetSdk 34`，JDK 17 + AGP 8.1.4

## 构建

```bash
# 默认：QuickJS（需要 NDK）
gradle :app:assembleRelease

# 无 NDK 时：纯 Java 引擎逃生口
gradle :app:assembleRelease -PuseRhino=true
```

> 仓库未提交 gradle-wrapper.jar。本地首次构建建议先执行 `gradle wrapper` 生成 wrapper，
> 之后即可使用 `./gradlew`；CI 直接使用安装的 Gradle，不依赖 wrapper。

QuickJS 源码与 Shizuku AIDL 由 `scripts/` 下的脚本在构建前按需拉取，
拉取失败不阻断构建：JS 通道自动降级，动作流与无障碍执行不受影响。

签名：在项目根放置 `signing.properties`（不在版本库内）：

```properties
storeFile=../autoball.jks
storePassword=***
keyAlias=autoball
keyPassword=***
```

## 目录结构

```
app/src/main/java/com/autoball/
├── core/
│   ├── backend/     双后端抽象、无障碍后端、Shizuku 后端、能力路由器
│   ├── engine/      动作流执行器、JS 宿主、QuickJS / Rhino 引擎
│   ├── model/       20 类动作、动作流、脚本、分组
│   ├── recorder/    采集层、回声抑制、手势编译
│   ├── store/       本地存储、分享码
│   ├── log/         环形运行日志
│   └── util/        条件求值、显示与权限工具
├── float/           悬浮球、悬浮窗、窗口管理
├── service/         无障碍服务、前台服务、Shizuku 客户端
└── ui/              五个页面、动态动作表单、坐标拾取
```

## 已知限制

- 坐标为 **绝对像素**，换机型或转屏会偏移，归一化支持规划在 v0.8
- 多指手势在无障碍通道依赖并行 stroke，部分厂商 ROM 会降级为单指
- 保活只能降低被回收的频率，**不能承诺不被系统杀死**
- Shizuku 非 Root 时每次重启需重新启动；无障碍服务开关由系统控制，应用无法自行恢复

## 合规

不申请设备管理器；所有动作由用户手动启动并可随时停止；
运行日志不记录输入文本、控件文本与分享码原文。
